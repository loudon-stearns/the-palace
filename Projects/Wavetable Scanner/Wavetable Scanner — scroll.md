### Where this stands

Wavetable Scanner is the page that draws a wavetable as a 3D landscape. It packs its own tables from a folder of single cycles, plays them as a browser synth, saves them for Serum, Vital, Surge and Ableton, and runs as a VST3/AU plugin with the landscape in the middle of its window. The plan's plugin step said the plugin should load a packed table, and until now it only played three built-in ones. This cycle closed that gap. The plugin's Table menu now ends in eight folder slots, read from ~/Music/Wavetable Scanner/Tables. I've put two of the study page's exports there for you to try.

## Plan

<!-- scroll:plan:start -->
Where it's going: a self-contained tool that turns any folder of single cycles into a morphable table you can see, hear and export, and an instrument that plays those tables in the browser and as a plugin in Live, whose tables and voice the Synth Templates catalog can use.

1. The packer in the page (done 2026-11-03): folder in, centroid-sorted table out, matching pack_wavetable.py.
2. Pack the way you chose (done 2026-11-04): the family-chain order and frame alignment from Generative Wavetable Libraries. The spectral morph (done 2026-11-04) replaces the blur as the smoothing between frames.
3. Finish Study (done 2026-11-04, two checks left by hand): Firefox and WebKit, folder drag-and-drop, dragging the cursor plane in the 3D scene, a test plan. Safari.app and phone touch are still untried.
4. An online MIDI synth (done 2026-11-04): wavetable_synth.html plays the tables from a MIDI keyboard or the computer keys, with the mod wheel on Position, band-limited tables, the Synth Templates envelope curve and the spectral morph.
5. The synth as a plugin through the VST Template: the same engine ported into Algorithm.h, a VST3/AU that loads a packed table, with the scanner's 3D view at the centre of its window, checked against the Node render of the same notes and with pluginval.
6. Plug into Synth Templates (my side done 2026-11-04): four wavetable cards play on this synth from their own words. Still to come: the growl card (an FM sine and drive), and, offered to that project for its yes, a wavetable source in its own voice and a table: field on its cards.
7. Export for the synths you use: Serum/Vital CLM WAV and Surge .wt beside the Ableton WAV.
8. Piece: a rendered demo scan, a per-table CPU and draw budget, and Loudon Live chrome. Then the question of whether a 2D scanner grows here or as its own project.

### 2026-11-04 — cycle 9 — The plugin now plays your own tables: drop Serum, Surge or Ableton tables into a folder and they appear in its Table menu.
> shipped · all plugin checks pass again · steward leans the mod wheel next

The folder slots read the files the study page's export buttons save: Serum/Vital CLM WAVs (resampled from their frame size to 1024 in the spectrum), Surge .wt files and plain 1024-sample WAVs. Each file goes through the same spectral morph and per-octave band-limiting as the built-in tables. That happens once, when the host prepares the plugin, never on the audio thread, and every instance shares the result. The first eight files by name fill the slots, so a number at the front of a name picks its slot. In Live, switch the device off and on after adding a file. An empty slot plays the fm chain, and the picture says so. A filled slot is drawn as level ground with the scan still moving across it, because the editor can't hand the picture the file's frames yet.

The check (tools/folder_check.py) loads the built-in tables' own frames from a float WAV and a Surge .wt, and they play bit for bit the same as the built-ins, through both the engine and the real processBlock. The Serum export plays within −141 dB of the Surge export of the same table. The 16-bit Ableton export lands at RMS −64 dB, with one tenth of a second at −52 dB peak where 16-bit rounding tips a phase lock on a quiet harmonic. A single 600-sample cycle is skipped. The five reference passages, pluginval, auval and the host check all pass again.

I passed over a file chooser: that needs a hook in the VST Template's editor code, which is that project's, not mine.

### 2026-11-04 — cycle 8 — The scanner now saves any table for Serum/Vital, Surge XT and Ableton, and reads Serum and Surge tables back in whole.
> shipped · export step built, checked in three browsers · steward leans plugin table loading next

packer/formats.js writes three containers. Serum and Vital get a CLM WAV: 2048-sample frames, float, laid out like Serum's factory 'Basic Shapes.wav'. Re-encoding that factory file gives the same bytes, so the layout is proven against a real Serum file. The 1024 → 2048 step uses the spectrum, so every harmonic in a frame is kept and nothing new is made. Surge XT gets a .wt in the layout from Surge's own 'WT fileformat.txt' (installed on this Mac): 1024-sample waves, float32. Surge's factory tables are 16-bit at half scale, and the reader handles those too. Ableton gets a plain 16-bit WAV of 1024-sample frames, the same shape as the crystal and Shepard tables you heard in Live in June. A table longer than a format allows (256 frames for Serum and Ableton, 512 for Surge) is thinned evenly with the ends kept, and the page says how many frames it dropped. The FM and organ family chains are exported into packer/exports/. Every format reads back to the same frames: below −178 dB for Serum, exact for Surge, −89 dB for Ableton, which is the 16-bit rounding. In Chrome, Firefox and WebKit I packed the 122 FM cycles, clicked each button, and every download matched the node export byte for byte. Dropping the Serum and Surge files back on the page read 122 frames each. The page's earlier checks (export, cursor drag, folder drop) still pass in all three. Generative Wavetable Libraries still lists a Surge .wt writer as undone in its plan. This one is in plain JS and is proven, so it could borrow it.

### 2026-11-04 — cycle 7 — The synth is now a VST3 and AU plugin, with the 3D landscape in the middle of its window, and it matches the browser synth bit for bit.
> shipped · installed, all checks pass · not yet opened in Live or heard

The engine (plugin/src/Algorithm.h) is synth/wt-synth.js ported line for line. The spectral morph and the per-octave band-limiting are ported too, and run once on the tables at load, so the plugin moves between frames exactly as the page does. The check doesn't use a numpy copy. The plugin is held against the browser synth's own engine, running in Node. The JS engine sets its slow values every 16 samples, so the C++ keeps the same 16-sample count and the test passages put every note and every move on those marks. Five passages, each checked sample by sample: the FM chain swept by hand, a cello chord with the mod envelope scanning, the classics under a triangle LFO with seven unison copies, legato with glide down to a C8, and nine notes stealing from eight voices. Four match to the last bit and the fifth to 3.6e-8 of peak. The real plugin, with its parameter smoothing and block automation, keeps the loudness within 0.4 dB on the hand sweep and within 0.0003 dB everywhere else. pluginval passes at strictness 5, and so do auval and the strict code-signature check. The host check loads both formats and hears every move. The editor fits from 1120 × 780 up. The landscape follows the plugin's own Position, including the LFO and the envelope, and dragging on it moves the Position knob, so it records as automation.

### 2026-11-04 — cycle 5 — The synth now has a spectral morph: no harmonic drops out halfway between two frames. It's the default, with crossfade one menu click away.
> shipped · three browsers pass · four A/B sweeps to hear · steward leans spectral as default

Why the blur was hard to hear: the blur changes the frames themselves, but what you hear *between* two frames is the playback crossfade, which mixes two waveforms. Wherever the two hold a harmonic out of phase, it cancels halfway. On the FM family chain, 70 of 121 neighbouring pairs lose a harmonic by more than 6 dB at the halfway point, and the worst loses 30 dB. On the Sketch's classics, the square → bell step dips almost 9 dB in level.

The fix has two steps (`packer.js` `spectralMorph`). First it **lines up the phases**: on a held note you hear each harmonic's level, not its phase, so each frame takes the previous frame's phases and keeps its own levels. Then it **fills the gaps from the spectrum**: between each pair it adds in-between frames where each harmonic's power moves in a straight line, up to 512 frames in all. After both steps there are no holes in any table and no level dips.

What I found along the way: the sweep buzz (the flutter on a fast sweep) is a different problem. It comes from how far apart neighbouring frames are, and only the blur reduces it. Filling the gaps *without* lining up the phases first made the buzz 5 dB worse, because each harmonic's phase has to turn, which is a small pitch wobble. That's why the phases get lined up first.

In the synth, the **Morph** menu next to Table defaults to *Spectral*. I matched loudness on energy, not peak, because lined-up phases make the waveform peakier. The two settings measure within 0.1 dB of each other in Chrome, Firefox and WebKit, and switching takes 150 to 200 ms on the FM table. A folder you pack in the synth isn't blurred any more; the morph does the smoothing.

### 2026-11-04 — cycle 4 — The scanner is now an instrument. Plug in a MIDI keyboard, play the scanner's tables, and the mod wheel moves you through the frames.
> shipped · plays in Chrome, Firefox, WebKit · steward leans plugin next

Open [the synth](open:Projects/Wavetable Scanner/wavetable_synth.html), click Engage and let Chrome use MIDI. It has eight voices with up to seven detuned unison copies each, a resonant 12 dB lowpass, an amp envelope and a mod envelope (to cutoff and to Position), an LFO, and poly, mono or legato with glide. The mod wheel moves Position, CC74 moves the cutoff, and the sustain pedal and pitch bend both work. It opens with three tables: the five classics, the cello table and the 122-frame FM chain. **Pack a folder…** packs single cycles and plays them at once.

Two things make it a real instrument rather than the scanner with keys added. First, every frame is band-limited once per octave, so high notes don't fold back as aliasing: a saw at C7 drops from −15 dB of alias energy to −57 dB. Second, the envelopes follow the Synth Templates standard, the Minimoog curve where a stage of T seconds reaches 95 % at T. Each time shows in seconds and as the nearest card word (*fast*, *medium*), so a card's words mean the same here.

The engine (`synth/wt-synth.js`) is one plain class with a per-sample loop. The browser runs it inside an AudioWorklet, and Node runs the same class for the proofs. That shape is what the VST Template's `Algorithm.h` takes, so the plugin will be a port of this code, not a rewrite. I also restored the three cycle-1 screenshots that had sat deleted and uncommitted for two cycles, so that loose end is closed.

### 2026-11-04 — cycle 1 — The scanner packs its own tables now: drop a folder of single-cycle WAVs on the page and it sorts, plays and draws them, no Python.
> shipped · checked against pack_wavetable.py on six AKWF folders · steward leans family chain next

Open [wavetable_scanner_study.html](obsidian://open?vault=The%20Palace&file=Projects/Wavetable%20Scanner/wavetable_scanner_study.html). It opens on a cello table that this same packer built from AKWF_cello. Click Engage, then Choose folder… and pick ~/Desktop/AKWF/AKWF_fmsynth: 122 cycles pack in about a tenth of a second. The HUD now says what the order means. Under centroid sort, the back ridges are brighter and the HUD shows each frame's brightness in Hz. Under file order it says depth means nothing. That answers the entry's open question about which order to use.

How it works. It does the same five steps as pack_wavetable.py, with one change. The Python script tiles each cycle three times through a filter and keeps the middle copy, so the filter never meets an edge. A single cycle's own spectrum is already perfectly periodic, so the page resamples in the spectrum and needs no tiling. Brightness, sort order, normalising together to 0.99, the 32-bit float output and the filename truncation all follow the script exactly.

One trap changed the design. The browser's built-in decoder (decodeAudioData) resamples every file to the audio device's rate. A 600-sample AKWF cycle decoded at 48 kHz comes back 653 samples long, so it's no longer one cycle. The packer reads the WAV chunks itself: PCM 8, 16, 24 and 32-bit, float, and extensible headers.

How I checked it. compare.py packed six AKWF folders with both tools (table). Up to the 250th harmonic the frames agree to −59 dB or better. Above that the two really differ: scipy's filter rolls off the top 50 or so harmonics of a 600-sample cycle, and the spectral resample keeps them. That top-end energy moves a few centroids by up to 40 Hz, so a few near-tied neighbours swap places. Then I drove the page in Chrome with the real file picker: 122 FM files, the HUD at both ends, the order toggle and the export. There were no page errors, and the downloaded table is bit-identical to the packer run in node. To try it in a synth or listen, see the [packer notes](obsidian://open?vault=The%20Palace&file=Projects/Wavetable%20Scanner/packer/BUILD.md).
