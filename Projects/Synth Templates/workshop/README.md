`build-catalog.py` is the source of truth; `catalog.json` and `picker.html` (via `build-picker.py`) are generated from it and are overwritten on every build. The tracker reads each card's `status` from `cards/*.yaml` at build time as a floor, so every card shows at least `drafted` on any machine; the browser can still raise a card to rendered or verified (2026-11-03). Loudon's synthesis notes, which seed the concept map, live in the bundle of [[Synthesis Notes (Loudon)]]: `Synthesis Notes (Loudon)/Synthesis Notes (Loudon) — source — notes.pdf` and `— notes-text.txt`.

## Cards and their sheets

A template is a card, `cards/<id>.yaml` (schema `synth-template-card/0.1`: identity, graph, essentials pinned with why, taste ranges default first, listening cue and A/B, render spec, mappings). `card-to-tikz.py` draws the card's signal-flow sheet under the [[Technical Diagram Standard]] with one fixed layout: sources stack in column 1 (column 0 is kept for modulators of the oscillators), then mix, filter 1, filter 2, amp, fx, out, each block's output jack at the height of its audio input so the chain is one straight line; the mixer takes one labelled input jack per source with its level bar on the row beneath it, growing taller with its inputs; modulators beneath, each in the column before its first target when possible (a second on the same target shifts right) so no wire crosses another; every wire orthogonal, horizontal and vertical runs only; every modulation wire runs in its own lane, offset so none stacks on another; performance inputs along the bottom; block titles in full (OSCILLATOR 1, MIXER, FILTER ENVELOPE, AMPLITUDE ENVELOPE, KEYBOARD…), the modulation envelope named for its role (PITCH ENVELOPE, INDEX ENVELOPE), mixer jack labels in full (Loudon, 2026-11-02: full names on the sheet); essentials in ink, taste in amber ([[Drafting Table Design System]] provenance colours); a modulation route with `polarity: negative` (or `inverted`) is labelled "− amount" on the sheet (2026-11-03). Only the blocks a card uses are drawn; the slot order is fixed, the positions are computed per card (Loudon, 2026-11-01). Schema `synth-template-card/0.2` adds typed fields the glyphs read: an oscillator's `wave`, `pw`, `unison`, `detune`; a filter's `type`, `slope`, `resonance`; an envelope's `shape` (`a`/`d`/`s`/`r` as words) and `category` (from [[Synthesis Notes (Loudon)]]); an LFO's `wave`, `rate`, `sync`; the FX block's `chain`. The generator draws each block's glyph from those fields in its upper right, never by hand (Loudon, 2026-11-01: add the graphics as you make them). The amp's glyph is a vertical fader, its cap at the block's `level` word (Loudon, 2026-11-02: "add an image of a vertical mixer fader"); the FX block draws one glyph per effect in `chain`, side by side: chorus three sines offset 60° in phase at three ink weights (his "multiple sine waves out of phase with each other"), reverb a decaying tail of reflections, delay or echo repeating impulses, saturation / drive / distortion a faint sine and its soft-clipped copy, phaser or flanger a rippled curve, anything else its name. Level words include `under unity` and `headroom`.

**Gotcha:** YAML reads a bare `on`, `off`, `yes` or `no` as a boolean. A card value meant as the word must be quoted (`value: "on"`); unquoted, it printed as `True`.

**Cable routes** (Loudon, 2026-11-02: "when possible reduce the number of turns in a cable, simplify the paths"). When a modulator's gutter lies ahead of its out jack and no drawn block stands across the run at that height, the wire is three segments: out, across to the gutter, up or down, in. Only when the target is behind the source, or a block is in the way, does it take the five-segment bus route under the row. An audio edge may name the jack it enters (`[osc2, osc1, fm]`), and a jack a route names that the block does not list by default is added to the block. An oscillator that feeds only another oscillator is a modulator and goes to column 0, level with its target: the standard applied to FM.

**Every catalog id has a card** since 2026-11-03: 292 in `cards/`, 287 of them drafted by a swarm of nineteen family agents on Loudon's "proceed", each with its `.tex`, `.svg` and `-preview-1.png`; all are `status: drafted` until heard. The swarm's brief and one catalog slice per family are in `_swarm/` (`BRIEF.md`, `<family>.md`), kept as the record of what each agent was told.

**The gate:** `validate-card.py cards/*.yaml` checks each card's schema, that every range word is in `vocabulary.yaml`, the slot grammar, agreement with `catalog.json`, and stray keys from an unquoted comma; `--render` runs it through `card-to-tikz.py`, `pdflatex`, PyMuPDF and `sips`. A card is not committed on a FAIL. **Gotcha:** a YAML value with a comma, `pitch, inverted`, splits into a stray key unless quoted; the validator catches it.

Render recipe, from this folder:

```sh
python3 card-to-tikz.py cards/<id>.yaml          # writes cards/<id>.tex
cd cards && pdflatex -interaction=nonstopmode -halt-on-error <id>.tex
python3 -c 'import fitz,sys; open(sys.argv[1][:-4]+".svg","w").write(fitz.open(sys.argv[1])[0].get_svg_image(text_as_path=True))' <id>.pdf
sips -s format png <id>.pdf --out <id>-preview-1.png   # quick look only
```

**Conventions adopted** (2026-11-01, on Loudon's read of the first sheet: "put all inputs on the left side of the blocks, and label all inputs"). Every block carries labelled input jacks on its left edge and its output on the right; flow runs left to right; modulation wires leave on the right, drop to a bus under the audio row, and rise in the gutter left of the target into its jack. Line styles: audio solid, CV dashed, gate dotted. Where these come from, outside the palace: inputs left, outputs right, left-to-right flow is the default IEC 60617-12 reading of a symbol ([IEC graphical symbols database entry](https://library.iec.ch/grasymb/grasymb.nsf/bfd81b91ec98490ec12566af007e4d43/a3c983643675b55ec125718e0047b35b/$FILE/A00269_EN.pdf)); solid audio / dashed CV / dotted gate-and-trigger is the three-line convention of *Electronics & Music Maker*'s "Guide to Electronic Music Techniques" ([muzines, March 1982](https://www.muzines.co.uk/articles/guide-to-electronic-music-techniques/4224)), and the Moog Sub Phatty manual's signal-flow page draws audio solid and control dotted ([manual, p. 12](https://www.manualsdir.com/manuals/279695/moog-music-sub-phatty.html?page=12)). The nearest text notation for a patch is Patchbook ([Spektro Audio, 2017](https://spektroaudio.squarespace.com/blog/2017/8/22/introducing-patchbook-a-markup-language-for-modular-synth-patches)): `->` audio, `p>` pitch, `g>` gate, `t>` trigger, `>>` any connection; the card's `graph.audio` / `graph.modulation` split mirrors that typing. Web sources, not palace canon.

The `.tex` and `.svg` are kept, per the standard's filing protocol; the `-preview-1.png` is kept as the quick look; the `.pdf` is ignored (`.gitignore`). The standard's own `render.sh` (`_ops/Technical Diagram Standard/render.sh`) stops at its dvisvgm step on this Mac — dvisvgm rejects the installed Ghostscript 10.07 — so the SVG comes from PyMuPDF instead (reported by the working session, 2026-11-01).

## Site

`build-site.py` reads `catalog.json`, `vocabulary.yaml` and `cards/*.yaml` and writes `site/index.html`, Drafting Table paper. The sheets are not inlined (292 of them would make a 40 MB page): `site/sheets` is a symlink to `../cards`, and the card page loads `sheets/<id>.svg` as an image, so the site must be served from `site/` with the symlink in place. Two views by hash route: the catalog (all 292 rows by family, search, a card badge and a With-cards filter) and the card page (title block, Play the default / Stop, a two-octave keyboard, the signal-flow sheet inline, essentials and taste with their why, listening cue and A/B, concepts, lineage, render spec). The reference voice is vanilla Web Audio interpreting the card's graph; Play the default reads the card's render pattern as prose cues (note unit, bars, held lengths, arpeggio, slides, rests) bounded by `length_s`, and scales a chord's voices by 1/√n (Loudon, 2026-11-03: "Yes, fix both"). Loudon, 2026-11-02: "I'd like to make this as a fully useable interactive website, we have a catalog we can choose from, pick one preset from the catalog and we see the card/page, it is playable in default settings."

Run it: `python3 build-site.py`, then the `synth-templates` entry in `.claude/launch.json` (python `http.server` on 8230 serving `site/`) or any static server on `site/`. `site/index.html` is generated; edit the cards, the vocabulary or the builder, never the output.

The card page answers Web MIDI: it asks for access, lists the inputs, plays note on and off with velocity on the open card, and CC 123 stops all; the on-screen keys carry no note names (Loudon, 2026-11-02). A Review box on every card page is saved in the browser, and Export reviews on the catalog copies all of them as markdown to paste back. The essentials and taste tables name blocks and parameters in full, Oscillator 1, Sub oscillator, Filter envelope, Amplitude envelope, Pitch envelope, Attack time, Decay time, Sustain level, Release time, Cutoff frequency, Envelope amount, never shortened, so a student sees the parameter's whole name each time (his rule). The release is `cancelAndHold` then `setTargetAtTime` with a time constant of release ÷ 3, the oscillators stopping after two release lengths; a linear ramp restarted from the read value could step and click.

The **Vocabulary page** (`#/vocabulary`, from the catalog toolbar) is where the sitting of Plan move 1 happens: twelve tabs, one per table in `vocabulary.yaml`, each row a word, a slider (log-scaled where the range is), the value in units and a hear button; the demo is one plain patch, a saw through a 24 dB low-pass into an amp, varied only in the word under test. **Envelope curves.** The standard is the Minimoog contour shape: every stage an exponential approach to its target (an RC charge, `setTargetAtTime` per stage), a stage's time being its 95 % point (tau = T ÷ 3). A linear curve is kept beside it as the second test. The time words are sat on both, in two tabs, `time · moog` (the standard, the `time` table) and `time · linear` (the `time_linear` table); a word is defined under its curve, so a number heard on one does not transfer to the other (Loudon, 2026-11-02: "matching a classic MOOG amp envelope curve … we want 2 tests, the MOOG curve, and linear"). Sources, web not palace: the AJH Synth MiniMod Dual Contour user guide, "very accurate replicas of the vintage Model D Contour Generators, with identical all transistor EG circuitry … the very fast exponential slope" ([gear4music copy](https://r2.gear4music.com/media/30/303400/download_303400.pdf)); Richard Atkinson on the W3C public-audio list, 2014, on comparator-switched RC envelope generators, the Minimoog among them ([lists.w3.org](https://lists.w3.org/Archives/Public/public-audio/2014JulSep/0058.html)). Each time tab has three modes chosen above its rows, as attack (rise over the word, hold 1.5 s, quick stop), as decay (instant start, fall to silence over the word) and as release (instant start, hold 0.8 s, fade over the word), so every note is the same length and only the one stage changes from rung to rung (Loudon, 2026-11-02). A hear button is a key, labelled hold to hear: press for the attack, let go for the release, lit while held; a percussive shape ends itself and ignores the lift (Loudon, 2026-11-02). Play the ladder runs every rung scripted, holding each one second past its attack. Moving a slider is silent; press hear to listen (Loudon, 2026-11-02). The moved number is held in the browser, and the card voices use it, so every card sounds with the tuned numbers. The loop: hear → move → mark "this table is heard" → Export vocabulary.yaml (each table marked HEARD with its date or ASSUMED) → paste to Claude, who writes `vocabulary.yaml` → `python3 build-site.py`. Reset this table to the file undoes. Every sounding button fires on the press, not the release, like a piano key, and swallows the click that follows; keyboard-driven clicks still work (Loudon, 2026-11-02).

**Reference renders** (Plan move 4). The voice is written to `site/voice.js` by `build-site.py` (the page loads it with `<script src>`); `render-refs.mjs` imports that same file in Node, hands it an `OfflineAudioContext` from the local `node-web-audio-api` package (`npm install` in this folder; `node_modules/` is gitignored) and calls the same `playDemo` the Play-the-default button calls, so the WAV and the browser are one voice. `node render-refs.mjs` writes `renders/<id>.wav` (48 kHz, 16-bit stereo, trimmed at the silent tail; WAVs are gitignored palace-wide), `renders/manifest.json` (the schedule per card: last note-off, release, fx tail), then runs `render-features.py` for `renders/features.json` (peak, RMS, crest, centroid, rise to -6 dB, tail to -40 dB after the last note-off, width, duration), `renders/<id>.png` spectrograms and `renders/SANITY-<date>.md`, the cards that are silent, clipping, off their `length_s` or using a word the vocabulary lacks, each with a likely cause. The renders use `vocabulary.yaml` as on disk, not the browser's tuned copy. Known: `playDemo` reads `tempo`, `note` and `velocity` but not `pattern` or `length_s`; it plays a chord 3.5 beats, a single note four times, a mono line as sixteenths.

`vocabulary.yaml` is the one place the cards' range words become numbers for the reference voice (time, level, cutoff, resonance, amount, pitch amount, detune, rate, glide, drive, fm index, reverb). Draft 0.1 is marked ASSUMED in its header: set by reasoning, to be earned by ear against the site's own voice. Known: `fm_index: half = 3` makes the FM piano hot.
