# The door: how the palace commits

The answer to the keeper handoff of 2026-10-13. Its page, with the diagram: https://claude.ai/artifact/GezVoiegoGJA3ztJtHvUr6

## The answer

No new agent. The keeper came apart into parts the palace already has.

- **Order on main** is a property of the committer every writer already calls: one lock the operating system holds (`_ops/stigmergy/app/server/door.js`), taken from the first `git add` to the commit by the command-line committer, the STIGMERGY server, steward cycles, the heartbeat and the Trickster's undo. Each commit holds only the files it names. Raw git typed by an agent does not pass the door; the ear hears it.
- **Landing a branch** is one command, `palace-land`, run by any session from its own branch (`palace-land HEAD`); the Concierge runs it for a branch that carries house writes.
- **The survey** is read-only and computed when someone looks: `trunk-state.mjs` now, a strip on the LOG deck later.
- **Pushing** stays Loudon's word, carried by `palace-push`, which sends exactly the tip he was shown and leaves a receipt.
- **Tending the history** goes to three rites where Loudon is in the room: Closing Well asks what a session leaves out, the Return opens with what changed since he left, the Weave decides what to clear.
- **The judgments** stay his: when to publish, work whose author is gone, a rewrite, deleting a branch that holds unique work.
- The Concierge keeps its heading, the keeper of the palace's shape, and meets other Concierges at the lock rather than by message. If after a month something still needs a holder, that remainder is the measured size of a keeper's job and comes back as its own proposal.

## Why

On 2026-10-13 main moved 118 times; 96 were direct commits, 46 by unattended stewards, so a keeper that lands branches would have governed 22. Raced on a throwaway copy, git's own locks left the shared index wrong in 9 of 17 trials and one lock held around every write left it right in 16 of 16. Across about 33 recorded mishaps every fix put into code held and every rule kept only in prose came back. A worktree-isolated agent is refused any git aimed at the main checkout, so it could not reach a keeper living there. A message between sessions in different permission modes is held and dropped, and a message can never stand in for Loudon's yes.

## Loudon's decisions, 2026-10-14

- The direction: no new agent for now; Policy 2 of the keeper baton retired; the door plus the rites, built lighter first.
- The history half goes to the rites. The survey may read other sessions' transcripts to name who left a file.
- A landing that died halfway is finished quietly when every file it changed sits at the old or the new version; a file at neither is someone's edit, left alone and named.
- Steward commits ride along when he pushes.
- Cowork is out of the design; he never commits by hand; his one hand path, the Trickster Commit, already goes through the door.
- Still his to click: GitHub's block-force-push rule on main.

## Roads not taken, and when to take them

- **No One Stands on Main**: Loudon's folder on a branch of its own, main held by an empty locked worktree. Take it if the ear's week shows raw git in the folder still moving main or wrecking the index.
- **Every Hand a Steward**: no model types git at the trunk; landing becomes a property of the next commit. Take it if sessions keep typing raw git past the refusals, or branches are left unlanded when sessions end.
- **The Lander**: one standing process with no model that lands and pushes; requests outlive their sessions. Take it if app-worktree sessions cannot land, or many sessions die between committing and landing.
