Two places

The gotcha says an AudioWorkletNode is mono unless you ask for stereo in two places: the constructor and the loop. Ask in one and not the other and you get a silent right ear or a thrown error. This walks up from one stereo tone to that claim, and then tries the defensive idiom the gotcha recommends on a node that wasn't asked. Nothing plays until you press sound. The meters say what each ear gets, so it reads without headphones too.

Step 1 of 4 · asked in both places

One worklet, two voices: a low one on the left, a higher one on the right

A stereo test tone. The worklet makes two voices, 330 Hz for the left ear and 495 Hz, a fifth above, for the right, and writes each into its own channel. The node was built with two output channels, and the loop writes both. This is the gotcha done right, so you know what right sounds like before anything goes wrong. Switch a voice off and its ear goes quiet.

// main thread
new AudioWorkletNode(ctx, 'two-places', { outputChannelCount: [2] })
// in process(), every sample
out[0][i] = left;   out[1][i] = right;

Step 2 of 4 · asked in the constructor only

The node has two channels, and the loop only fills one

Same node, built with two output channels. But the loop writes only the first. The second channel is there, and nothing goes in it, so the right ear gets silence: not the left voice copied over, not a fallback, nothing. The voice meant for the right ear isn't anywhere.

new AudioWorkletNode(ctx, 'two-places', { outputChannelCount: [2] })
out[0][i] = left;   // out[1] is never written

Step 3 of 4 · asked in the loop only

The loop writes two channels, and the node was never asked for two

Now the other way round. The loop is step 1's, writing both channels. But the node was built without asking, and a node with no input and no channel count gets one output channel. So out[1] isn't there, and writing into it throws on the first sample. The node reports a processor error and stops for good: both ears silent, until the node is rebuilt. The context survives; only the node is gone.

new AudioWorkletNode(ctx, 'two-places', { numberOfInputs: 0 })   // no outputChannelCount
out[0][i] = left;   out[1][i] = right;   // out[1] is undefined: this line throws

TryPress sound. Nothing, in either ear, and the processor line says why. This is the "thrown" half of the gotcha: the throw is a TypeError on the missing channel, and what it costs is all the sound, not half.

Step 4 of 4 · the test

The defensive idiom keeps the loop from throwing. Does it keep the sound?

The gotcha's cure for a host that gave one channel is the line const outR = out[1] || out[0]: when there is no second channel, write the right voice into the first. It stops the throw. But a loop that writes left and then right into the same channel leaves only the second write, so one voice is lost. Murmuration's instrument guards the second write instead, which loses the other voice. The third loop folds both voices into the one channel when it's alone. Try each on a node that wasn't asked, then ask.
