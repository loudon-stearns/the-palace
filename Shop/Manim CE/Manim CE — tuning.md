# Manim CE — tuning

What each job taught the Manim CE page. Each item names what the job showed and what changed because of it, if anything did. Newest last. Items 1, 3, 5–7 and 9–11 are the page's dated gotchas, moved here on 2026-11-08 when the page's Gotchas became present-tense rules. Items 2, 8 and the frozen-arrow bug story in item 3 are the statements the 2026-10-24 Weave took off the page as doubles (`a75350ec`), which [[Manim CE — Context]] held back for this ledger; the K_c miscalibration in item 4 is the other run lesson it named. Seeded history carries no run lines, as FLUX's doesn't, except the 2026-06-09 line, the date the page's `last_tested` kept. The undated community watch-list stays on the page until a job hits one.

## From the Round 1 install — 2026-05-10

1. **`pycairo` is source-only on PyPI,** with no wheels for any Python version on macOS arm64, so `pip install manim` always builds it. Without the system libraries the build fails with a confusing `meson` error (`Did not find pkg-config`). Symptoms were identical on Python 3.13 and 3.14. Changed: `brew install cairo pkg-config pango` comes first (§ Install).
2. **Python 3.14 was too new for the dependency tree:** even with system cairo installed, several transitive deps lacked 3.14 wheels (May 2026). Changed: use Python 3.13 via Homebrew, until pycairo publishes 3.14 wheels. The statement now lives once, in § Install.

## From the sync-arriving job — 2026-05-26 — Study tier, 720p30, 36.5 s

3. **Arrows mutated from a foreign updater never moved.** The first render attached an `update_all(_mob, dt)` closure to a dummy `Mobject()` driver; it called `arrows[j].put_start_and_end_on(start, tip)` and `set_color(col)` every frame. The HUD (`always_redraw(lambda: Text(...))`) updated, proving the updater fired, but the arrows sat at their `t=0` positions for all 36 s — frames at 1 s, 20 s and 35 s were pixel-identical for the arrow group, caught by visual frame inspection of the muxed video. Root cause: Manim CE 0.20.1's renderer re-extracts geometry only for mobjects whose `become()` is called or whose factory is wrapped by `always_redraw`; in-place point mutations reached from another mobject's updater are dropped. Changed: every phase arrow and the R-vector became `always_redraw` factories reading a `ValueTracker` clock (`071ae3b7`), at the cost of a small per-frame allocation. The recipe's own copy of this bug story was the double the 2026-10-24 Weave removed.
4. **The first render's physics told the wrong story.** σ = 0.25·2π rad/s put K_c ≈ 2.5, but K_end was 1.2, below threshold; the narration ended with |R| ≈ 0.46, partial coherence, not lock. The on-screen K_c caption had carried the two-phasor case's K_c ≈ 0.22 (`a94481f0`). Changed: σ = 0.30 rad/s, so K_c = 2σ·√(2/π) ≈ 0.48, and K_end = 3·K_c; final |R| ≈ 0.99, and the caption reflects the actual distribution (`071ae3b7`). The lesson stays in the recipe's calibration story: compute K_c from the distribution before choosing K_end.
5. **Manim's default Pango font gapped letters in `Text` above size 36,** around `iv` and `ri` pairs; Loudon caught a visible gap in "arriving" in the title "Synchronization arriving" at the first review. Changed: `font="Georgia"` for the title. But Georgia below font_size ≈ 22 dropped inter-word spaces (`"8 oscillator phase dials"` rendered as `"8oscillatorphase dials"`), so the policy is two fonts: Georgia for large titles, Manim's default for small labels. Verified by extracting frames after each render.
6. **`DecimalNumber` (and any `MathTex`/`Tex`) needs LaTeX.** Manim CE 0.20.1 renders `DecimalNumber` through `SingleStringMathTex`, which shells out to `latex`; with no TeX the render crashed with `FileNotFoundError: 'latex'` deep inside `subprocess._execute_child`, a misleading trace. Changed: live numeric HUDs use Pango `Text` under `always_redraw(lambda: Text(f"K = {value:.2f}"))`, keeping the install small; install TeX (`brew install --cask mactex-no-gui`, ~4 GB) only when on-screen math needs real typesetting.
7. **With the Kokoro WAV and Whisper JSON already in hand, `manim-voiceover` would redo work and add a heavy dependency.** Changed: render the scene silent at exactly the narration's length (`self.wait(DURATION)`), let the Whisper JSON drive timing in the Python source, then `ffmpeg -i silent.mp4 -i narration.wav -c:v copy -c:a aac -shortest out.mp4`. Measured drift at 36 s: 25 ms (video 36.500 s after frame quantization at 30 fps, audio 36.475 s) — below perceptual threshold and well below the ~3-minute drift warning for `manim-voiceover`.

## From the tier ladder — 2026-05-30 — two phasors, uncoupled, Sketch → Study → Piece

8. **basictex alone was not enough for the LaTeX pipeline** — so it seemed that day. basictex ships `latex`/`pdflatex` but not `dvisvgm`; `brew install dvisvgm` pulled in brew's full `texlive` (≈4.6 GB), yet brew's `dvisvgm` searched under `/opt/homebrew/Cellar/dvisvgm/3.6/share/texmf-*`, so even with both installed it could not find `tex.pro` / `texps.pro` / `special.pro` / `color.pro`. Manim's message, *"Your installation does not support converting .dvi files to SVG. Consider updating dvisvgm to at least version 2.4,"* misled: 3.6 was installed; the problem was path resolution. Changed: a hardcoded-version `TEXPSHEADERS` export before invoking manim, with basictex on PATH; the cleaner `sudo tlmgr install dvisvgm` was not taken. Superseded by item 11, which showed the "basictex is incomplete" framing was wrong.
9. **First real tier-cost data, same Mac, same 10 s two-phasor content** (M-series, Manim CE 0.20.1, Python 3.13 via pipx). Sketch 5.4 s (`-ql`, 480p15, off-system palette, no LaTeX); Study 11.2 s (`-qh`, 1080p30, Graphite skin from [[Loudon Live Design System]] tokens, no LaTeX); Piece 15.9 s warm, 75–90 s cold first run (`-qh`, 1080p30, full `MathTex`, eased `FadeIn`s, the locked type stack, the footer). Study is ~2× Sketch and warm Piece only ~1.5× Study: the cost gap between tiers is the LaTeX pipeline and annotation rework, not pixel count. Piece is cache-dominated — a fresh host can spend 60–80 s generating Metafont fonts (cmr10 and the rest) on its first equation; reused equation strings drop to ~16 s. Changed: quote a fresh host's first Piece honestly, apart from steady state. Artifacts: `Kuramoto Coupling/two-phasors-uncoupled-{study,piece}-1080p30.mp4` and their sources. The page's Tiers blocks have not taken these numbers in (see [[Manim CE — Context]]).
10. **Tight layouts on a dark background made every annotation a placement decision.** The Piece's beat-period caption (`T_{beat} = 1/|f_A - f_B| ≈ 14.29 s`) took three placements: above the axes at left crashed into the `ω_A/2π` label; below the axes crashed into the footer; centred above the axes, in the empty band between the phasor circles, was right. Only the rendered frame at 5 s exposed each collision. Changed: render a frame at the scene's busiest moment before promoting Study to Piece, and count frame extraction as part of the Piece self-check, not a debug step.

## From the TeX re-check — 2026-06-09 — full Homebrew TeX Live 2026

11. **Full TeX Live did not fix the `dvisvgm` bug; the root cause was re-pinned.** On `/opt/homebrew/Cellar/texlive/20260301`, Manim CE 0.20.1, Python 3.13.2, `kpsewhich tex.pro texps.pro special.pro color.pro` resolved all four under `…/texmf-dist/dvips/base/`, and a bare `MathTex` still failed with *"Your installation does not support converting .dvi files to SVG."* The standalone Homebrew `dvisvgm` formula owns `/opt/homebrew/bin/dvisvgm`, and TeX Live's own `…/bin/dvisvgm` is only a symlink to it (confirmed), so there is no second, correctly-pathed binary; its kpathsea, rooted under `/opt/homebrew/Cellar/dvisvgm/3.6/…`, never searches the TeX Live tree. Pointing `TEXMFCNF` at TeX Live's `web2c` did not fix it; the version-agnostic `TEXPSHEADERS` bridge from `kpsewhich -var-value=TEXMFDIST` did, and survives `brew upgrade`. With it, `MathTex(r"\theta_A(t)=\omega_A\,t,\ \frac{\omega_A}{2\pi}=1.00\ \mathrm{Hz}")` rendered (Sketch `-ql` → PNG); without it the render died at `convert_to_svg`. Changed: the export was centralized in `Shop/Maker/tex-env.sh`, and on-screen-LaTeX renders dispatch through it (`Shop/Maker/tex-env.sh manim -ql scene.py Scene`). The [[LaTeX]] Specialist, born the same session (`fff24368`), inherits the gotcha for its SVG-cutout path. The structural fix, `sudo tlmgr install dvisvgm` into the TeX Live tree, stays untaken: it needs a sudo round-trip and would have to survive `brew` re-linking. The PDF path never touches `dvisvgm` and is unaffected.
