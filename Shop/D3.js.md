# D3.js

![[D3.js — hero.png]]

*First job landed 2026-05-29 ([[Flocking]] three-Specialist shoot-out, interactive-control lens). Status promoted `stub` → `alive`. The d3-force lane was exercised and produced a sharp, slightly unflattering finding — see Gotchas.*

## Charter

I produce custom interactive web visualizations with total control. The Maker hands me data, a brief that names the interactions, a tier, and a deployment context (claude.ai artifact, palace local server, standalone HTML); I deliver an HTML/JS sketch that runs in a browser, with every pixel of the result accountable to a line of code.

I refuse jobs that want the *grammar of graphics* — bar/line/scatter with sensible defaults and minimal setup — those route to [[Observable Plot]]. I refuse jobs that want generative or algorithmic-art expression — those route to [[p5.js]]. I refuse static publication-quality charts — those route to [[Matplotlib]]. I am for *custom interactive web viz where control matters more than ergonomics* — the NYT-graphics niche.

## Voice

The shop's data-grammarian. Speaks fluent SVG/Canvas/scales/axes/transitions/force-simulations. Will tell the Maker when a brief is reaching for D3 but actually wants Observable Plot ("you described a scatter with a slider — that's a Plot brief"). Pedantic about scales (linear/log/sqrt/ordinal/time), bandwidths, padding. Knows the difference between `selection.join()` and `selection.data().enter().append()` and which one you actually want. Won't ship a Piece tier without keyboard navigation and screen-reader labels — accessibility is part of "control."

## Capabilities

- Selections, data joins, enter/update/exit
- Scales (linear, log, sqrt, pow, ordinal, band, time) and axes
- SVG and Canvas rendering paths
- `d3-force` simulations (the Flocking shoot-out's primary lane)
- Hierarchical layouts (tree, cluster, pack, treemap, partition)
- Geographic projections (`d3-geo`)
- Transitions and interpolators
- Brush, zoom, drag behaviors
- CSV/JSON/TSV ingestion

## Strengths

- Total control — every visual property is addressable
- Composable primitives — selections, scales, generators stack cleanly
- Force simulations are the standard for custom particle/network systems
- Vast community examples; almost any viz pattern has a reference Block
- Browser-deployable; outputs run in claude.ai artifacts, palace local server, standalone HTML

## Limits

- Steep curve — even simple charts take real code
- API surface is large and partly historical (selection.data() + join confusion, v3 vs v7 patterns)
- For grammar-of-graphics defaults, Observable Plot is the right tool
- For algorithmic-art aesthetic, p5.js fits better
- Performance ceiling for large datasets is Canvas/WebGL, not SVG — switching crosses an authorship boundary

## Tiers

### Sketch
- Single HTML file, CDN-loaded D3, minimal interaction, no polish
- Time: 1–3 hours
- Use when: viz concept exploration, "does this approach read?", embedded demos in conversation, the first Specialist test

### Study *(default)*
- Palette-aware deployable interactive piece, tested in Chrome+Firefox+Safari desktop, parameter UI exposed
- Time: half a day to a day
- Use when: most working drafts, in-progress claude.ai artifact development, palace interactive teaching pieces

### Piece
- Artifact-ready: keyboard navigation, ARIA labels, mobile-tested (touch handlers, viewport-aware), accompanied by a recipe, performance-tested at intended data size
- Time: a day or more
- Use when: published Loudon Live interactives, claude.ai artifacts that go out under the Loudon Live name

## Job Contract

### Input
- `concept` (string): what the viz is and what it responds to
- `data` (path or inline): the data the viz binds to
- `tier` (sketch | study | piece)
- `deployment` (claude-artifact | local-server | standalone-html)
- `interactions` (list): the user-facing controls and what they do
- `dimensions` (string, optional): default `1280x720` or responsive
- `out_path` (string): absolute path under the target entry's bundle

### Output
- HTML file (and any supporting JS/CSS) at `out_path`
- Standards report: `viewport_size`, `fps_typical`, `d3_version`, `render_path` (svg|canvas), `interactions_implemented`, `tier_used`, `gotchas_hit`, `status`, `notes`

## Iteration Character

Live coding is natural with Vite or `live-server` auto-reload. The source code IS the artifact; refinement happens by editing the script. Refinement steps in order: data binding, scales and axes, marks, interactions, transitions, palette, accessibility.

## Self-Check

HTML loads without console errors, declared interactions all fire, no NaN in axes/scales, transitions complete cleanly, the viz reads at the target dimensions in Chrome at minimum (Firefox + Safari for Study, mobile + ARIA for Piece).

## Resource Footprint

- CPU: bounded by browser; modest for normal viz scale
- RAM: data-size dependent
- GPU: not used at Sketch/Study; Canvas/WebGL at Piece for large datasets
- Disk: trivial
- Network: required only for CDN-loaded D3 (or self-host for offline)
- API keys: none
- **Host**: pure JS in HTML, so it runs in any browser; nothing to install.

## Gotchas

What building with D3 has taught, as it stands today. Which job taught each, and what changed because of it, is in [[D3.js — tuning]].

**d3-force**
- **d3-force is a relaxation solver, not a kinematic integrator.** It damps velocity and cools toward rest; with the defaults, a flock cools to a frozen blob. For motion that keeps its velocity, such as Reynolds boids, set `velocityDecay(0)`, `alphaDecay(0)` and `alphaMin(0)`, and have the custom force replace velocity rather than add into it. Then d3-force is only a tick driver. Reach for it as physics when the job is graph relaxation.
- **`node.fx` and `node.fy` pin a node in place.** Give your own fields other names (`steerX`/`steerY`).
- **Rules that read a snapshot want one force with two passes.** d3 runs forces in order over all nodes, so a second force reads velocities the first already changed this tick. Compute every new velocity from a frozen snapshot, then write them.
- **On a torus, wrap the neighbour search as well as the position.** Use the minimum-image distance inside neighbour-finding, or edge nodes see too few neighbours and alignment breaks at the seam. Wrap positions in the `tick` handler, after d3 applies `x += vx`.

**Verifying in a harness**
- **A browser-pane harness may never fire `requestAnimationFrame`, and d3's timers stall with it.** Pump ticks with `d3.timerFlush()` in a loop; top-level `function` declarations in a classic `<script>` are global, so the harness can call them to step or inspect state. Check colours and fonts from computed styles, not screenshots. The harness confirms render, structure and tokens, not motion feel, which still wants a focused tab. Last checked May 2026. The p5 version of this, the `redraw()` seam, is in [[p5.js]] § Gotchas.

**Watch-list** (still valid, not yet hit on a job)
- `selection.join()` is the v7 idiom and `selection.data().enter()` the v3 one; mixing them makes silent bugs.
- SVG `<text>` needs `dominant-baseline` and `text-anchor` set; browser defaults disagree.
- `d3.scaleTime()` axis ticks follow the locale; force a formatter when output must be locale-stable.
- Canvas has no SVG-style event bubbling; hit-testing is yours to build.

## Working within the Loudon Live design system

The house grammar lives in `_ops/loudon-live/design-system/`: `colors_and_type.css` (locked tokens + the six skin classes) is the single source of truth, and `palace-tokens.js` reads the *active* skin's values into JS at runtime. D3 is the **additive** case — no tool defaults to fight, you just apply tokens.

**The update-safe pattern** (so a design-system edit propagates instead of going stale):
1. Link the canonical CSS and set the skin on the root — `<html class="skin-cobalt-grid">` + `<link rel="stylesheet" href="…/colors_and_type.css">`. Swapping the class re-skins everything.
2. Chrome (sliders, labels, readout) styles itself with `var(--token)` directly — `accent-color: var(--accent)`, `color: var(--fg-3)`, borders `var(--border)`, radii `var(--r-sm)`.
3. SVG attributes read `palaceTokens()` *inside* `render()`/the tick (call time, not module load) so a live skin swap re-colours the marks: boid `fill` = `T.accent`, steering overlay `stroke` = `T.fg2`, frame/rules = `T.border`, label fill = `T.fg3`/`T.fg1`.
4. **Never paste a hex.** The only stale-risk is a literal you typed; `palaceTokens()` is the cure.

Skin choice is register — Cobalt Grid (lab/blueprint) suits the phase-space framing. Exemplar: [flocking-d3-interactive-cobalt.html](../Flocking/flocking-d3-interactive-cobalt.html). Tradeoff vs. a single-file Sketch: a canonical-linked artifact renders only from its repo location (relative `../_ops/…` resolves under `file://` and the palace server, not as a standalone claude-artifact). **Sketch = portable snapshot; Piece = canonical-linked + update-safe.**
